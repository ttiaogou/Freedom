# Freedom

Freedom 是独立的原生 Android Kotlin 项目，用于监听用户指定应用向 Android 无障碍服务公开的界面事件和节点信息。默认监控目标为陌陌 `com.immomo.momo`。

## 已保留的基础功能

- AccessibilityService 监听指定包名的无障碍事件。
- 事件名称和控件类型提供中文说明，同时保留原始事件名称和类名。
- 事件记录保存在本机，最多保留最近 300 条。
- 单次节点扫描最多访问 3000 个节点，最多展示 140 个节点预览。
- 可拖动的实时监控悬浮窗，支持收起、展开和停止监听。
- 默认收起时显示标题、服务状态、当前应用和当前页面。
- 展开后显示实时事件与节点预览；默认展开高度约为屏幕高度的三分之一。
- 展开后可拖动窗口底部的尺寸把手，手动调整悬浮窗宽度和高度；尺寸保存在本机。

## 稳定性处理

1. **无障碍服务恢复**：Android 系统重新绑定 AccessibilityService 后，Freedom 读取已保存的监听意图、目标包名和权限状态，并按设置恢复悬浮窗。
2. **前台服务保护**：用户主动开始监控时，可启动带持续通知的 `specialUse` 前台服务；服务采用 `START_STICKY`，系统回收进程后允许系统尝试重建。监听主体仍然是 AccessibilityService。
3. **开机检查**：接收 `BOOT_COMPLETED`，在用户此前要求继续运行且开启开机检查时，检查无障碍和悬浮窗授权，并发送启动检查通知。系统/厂商的自启动限制不能由普通应用统一读取或绕过；请在手机系统设置中允许 Freedom 自启动和后台运行。

前台服务不是绝对保活保证。用户强行停止应用、撤销无障碍授权、关闭悬浮窗权限、厂商后台策略或系统资源压力仍可能中断运行。Android 版本和手机厂商会影响恢复行为。

## 权限

- 无障碍服务：接收指定应用的界面事件并读取系统公开的节点。
- 显示在其他应用上层：展示监控悬浮窗。
- 前台服务：在用户主动运行监控期间显示持续通知并提高进程重要性。
- 开机完成广播：检查重启后的授权状态。
- 通知权限为可选；拒绝通知权限不会代替或授予无障碍/悬浮窗权限。Android 13 及以上如果关闭通知，开机检查通知可能无法显示。
- 照片和视频读取权限沿用原项目的可选设置；当前监控功能不依赖它。

## 构建

GitHub Actions 使用 JDK 17、Android SDK 35 和 Gradle 8.9 构建 Debug APK。

```bash
gradle --no-daemon clean assembleDebug
```

APK 输出路径：`app/build/outputs/apk/debug/app-debug.apk`。

Actions Artifact 只上传 APK 文件；推送 `v*` 标签时，工作流会将 APK 作为 GitHub Release 资产发布。

## 使用提醒

首次使用需要手动开启 Freedom 无障碍服务和悬浮窗权限。两项授权缺少任意一项都不能开始监控。Freedom 只读取目标应用通过 Android 无障碍接口公开的信息；它不能保证读取应用内部所有数据或每一条消息。监控记录仅保存在本机。
